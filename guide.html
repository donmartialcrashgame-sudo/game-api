Welcome to your developer dashboard

THE BASIC WORKFLOW
1

Secure your account

Open Security and enable an authenticator if you want two-factor protection. You can also manage browser/mobile push notifications from Settings.

2

Understand your plan

Open Plans to see your current plan, request allowance, and available upgrades. Your current paid plan is shown as the active plan.

3

Create an API key

Go to API Keys, create a key with a clear name, and keep the secret private. Treat an API key like a password: do not publish it in frontend code or public repositories.

4

Test your API

Use Test API before connecting your application. Select an endpoint, add your API key, send the request, and inspect the response.

5

Connect your application

After a successful test, use the endpoint and authentication format shown in Documentation. Keep your secret on your server whenever possible.

6

Monitor everything

Use Usage for request activity, Status for service health, and Live Stream for realtime game events.

Recommended order: Security → Plans → API Keys → Test API → Documentation → Usage/Live Stream.

WHAT EACH DASHBOARD AREA DOES

Dashboard: account overview, plan, request capacity, API health, and quick actions.

API Keys: create and manage credentials used to authenticate requests.

Test API: send controlled requests without building your application first.

Usage: review API request consumption and remaining capacity for the current period.

Projects: organize your development work as your integration grows.

Live Stream: connect to realtime game events through the WebSocket service.

Documentation: endpoint references, authentication guidance, request examples, and integration information.

Status: check whether the public API and realtime services are available.

Plans: review your subscription and available plan options.

Security: manage authenticator-based two-factor authentication.

Settings: manage account preferences and notification permissions.

IMPORTANT SECURITY RULES

Never post your API key in GitHub, screenshots, public websites, chat groups, or frontend JavaScript that visitors can inspect.

If a key is exposed, revoke it from API Keys and create a replacement.

Use HTTPS for your application and keep authentication credentials on your backend where possible.
